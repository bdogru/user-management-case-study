# Plan: Step 2 — Frontend

## Context

Step 1 delivers the API at `/api/users`, with the contracts in [step-1.md](step-1.md). Step 2 adds the
single Angular screen and a CI job that builds it.

## Core contracts (locked up front)

1. **App.** Angular 22 in `frontend/`, generated by `ng new` without routing, SSR and tests, with
   plain CSS. The generated placeholder content is removed. One component, the generated `App`,
   calls `HttpClient` directly; there is no service, because removing one would break nothing.

2. **Screen.**
   - A table with name and email, and Edit and Delete buttons on each row.
   - One form with name and email. Create mode: both editable, a Create button. Edit mode: name
     editable, email shown in a read-only input, Save and Cancel buttons.
   - One error line under the form: the `detail` of the last failed request, or the HTTP error
     message when there is none (backend not reachable). It is cleared when the next request starts.
   - After every successful create, update or delete: reload the list and return the form to create
     mode.
   - Delete acts at once, with no confirmation dialog.

3. **Requests.** Create sends `name` and `email`. Update sends `name` and the `version` of the row
   being edited, never `email` (step 1, D1 and D2).

## Decisions (proposed)

### D5 — How the browser reaches the API: the Angular dev-server proxy

`frontend/proxy.conf.json` forwards `/api` to `http://localhost:8080` and `angular.json` refers to
it; the client calls `/api/users`. Same-origin requests need no CORS configuration in the backend and
no backend URL in the client. Alternative: `@CrossOrigin` on the controller and an absolute URL.

## End-to-end result

Run on 2026-11-23 against the frontend of commit `6aa5759` (the head of PR #4) and the backend from
`main`, in the browser pane of the Claude desktop app on Windows 10: **B1–B10 pass**. Clicks and
typing went through the page's controls. Request bodies were recorded by wrapping `fetch` (Angular 22's
`HttpClient` uses it), cross-checked against the browser's network log. All requests went through the
dev-server proxy.

- B7 and B9: the PUT body is `{"name":"…","version":…}`, without `email`.
- B8: no request, per both the recorder and the network log.
- The console shows only the browser's network lines for the intended 400 (B3) and 409 (B4, B9).
- A first B6 attempt failed because of the automation, not the app: the app is zoneless and renders
  just after the click, and the script typed into the email field before the edit-mode render. With a
  one-second pause after each click, as a person would interact, B6 passes.

## Risks

- `ng new` asks questions (analytics, AI tooling) that an agent cannot answer; every answer is
  passed as a flag.
- The CLI generates more than the screen needs. Every generated file is checked against the
  "keep it small" test and removed if nothing needs it.
